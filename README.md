# choi.jae.one

nginx는 `web/`을 사이트의 문서 루트(`/`)로 서빙합니다. `/pages/`, `/files/`, `/posts/`는 각각 문서 루트 밖의 `pages/`, `files/`, `posts/`를 별도 경로로 서빙하며 JSON autoindex를 사용합니다. 루트의 `README.md`는 문서 루트 밖에 둡니다. 브라우저 라이브러리는 `web/vendor/`에 있습니다.

- `pages/<이름>/page.md`가 있는 폴더마다 files/posts 앞에 탭이 생깁니다. main은 `pages/main/page.md`에서 읽으며 기본 탭입니다. 이미지와 파일은 해당 페이지 폴더에 함께 두고 `./파일명`으로 참조할 수 있습니다. `/files/`의 항목은 마크다운에서 `/files/경로`로 직접 링크합니다.
- 글 하나는 `posts/<제목>/post.md`에 둡니다. 이미지 등 글의 자산도 같은 폴더에 둡니다.
- 마크다운에는 `![설명](./image.png)`처럼 상대 경로를 씁니다. 사이트의 글 보기와 편집기 미리보기가 글 폴더를 기준으로 이미지를 읽습니다.
- 새 글 명령은 제목 폴더를 새로 만들므로 기존 폴더를 덮어쓰지 않습니다. 수정 명령은 `post.md`가 있을 때만 덮어씁니다. 기존 글의 제목은 잠금을 풀어 바꿀 수 있습니다. 새 폴더명이 서버에 없는지 확인한 뒤 폴더 변경 명령을 복사하고, 실행 후 `제목 변경 확인`을 누릅니다. 변경 확인 전에는 본문 저장 명령이 비활성화됩니다.
- files 목록은 `files/`와 `web/links.json`의 같은 이름 폴더를 하나로 합쳐 보여줍니다. 항목과 폴더에 static/link 출처를 작게 표시합니다.
- 링크 항목을 선택하면 삭제하거나 제목·URL·폴더를 바꾸는 명령을 복사할 수 있습니다. 명령은 선택 당시 항목이 `web/links.json`에 그대로 있는지 확인하고 실행되며, 삭제·이동 뒤 비어 있는 링크 폴더를 제거합니다. 실행 뒤 페이지를 새로고침하면 목록이 갱신됩니다.
- static 파일 업로드는 SCP만 사용합니다. 로컬 경로를 입력하면 서버 파일명이 경로의 파일명으로 채워지고, 서버 파일명은 따로 바꿀 수 있습니다. 폴더가 없으면 `mkdir` 명령을 먼저 실행합니다.
- 글 본문은 편집기에서 만든 SSH 텍스트 저장 명령으로 저장합니다. 새 글 제목은 `/posts/<제목>/`의 존재 여부를 먼저 확인하며, 새 글 명령 실행 후 `글 생성 확인`을 누르면 수정 모드로 전환됩니다.
- 이미지는 파일 선택 없이 로컬 경로와 서버 이미지 이름을 행마다 입력합니다. 이름이 비어 있으면 경로의 파일명으로 채웁니다. 여러 행의 SCP 명령을 각각 실행한 뒤 `업로드 확인`을 누릅니다. 확인된 이미지는 현재 커서에 마크다운 참조 또는 너비를 지정한 HTML `<img>` 태그로 삽입할 수 있습니다. HTML 태그 뒤에는 빈 줄을 넣습니다. 미리보기는 서버 이미지를 읽습니다. 같은 이름의 기존 파일도 확인 대상으로 간주합니다.
- 이미지 파일의 바이트를 명령에 넣지 않으므로 큰 이미지가 글 편집이나 명령 생성 속도에 영향을 주지 않습니다.
- 글 작성기 툴바의 `미리보기` 버튼을 다시 누르면 수정 화면으로 돌아옵니다.
- `web/main.js`는 탭/복사를, `web/shared.js`는 공통 함수를, `web/files.js`와 `web/posts.js`는 각 탭의 기능을 담당합니다. 생성되는 원격 명령은 `web/links.json`, `files/`, `posts/`의 실제 저장 경로를 사용합니다.
